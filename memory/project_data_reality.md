**Why**: 用户最初的方案基于几个错误假设(千万级用户、画像可切、话题字段可靠、图稀疏)。多轮抽样探查(3 个 zip 各 3 csv → 单 zip 全量 122 csv 索引)推翻了部分假设,验证了另一些。

**How to apply**: 后续算法选型以下面这些验证过的实况为约束。**注意区分"3 csv 小样本"和"单 zip 全量索引"两级证据强度**。

## 数据体量(实测)
- 三批数据总体积:zip 压缩后至少 100GB,解压后 **200GB+**
- 重大议题 8 个 zip:每个 2-14 GB(生育话题分4个 zip 共 43GB)
- 热点事件 263 个 zip:每个 30MB-1GB
- 传播案例 114 个 zip:每个几十 MB
- 单议题 zip 内 122 个 csv,每 csv 通常 30-300 MB

## Schema
- **编码 GB18030**(GBK 的超集,兼容 GBK 且能处理生僻字。用 encoding='gb18030' + errors='replace' 兜底)
- 55-56 个字段
- CSV 有异常行,读取需 `on_bad_lines='skip'`

## 关键字段填充率
- **100% 或近100%**:日期、微博情绪、精准地域、涉及行业、涉及词、原创/转发、媒体类型、粉丝数、MD5-作者ID/mid/id/父微博ID
- **NULL哨兵混入**:MD5-根微博mid 5-13% 是空哨兵,MD5-根微博用户UID 87-95% 是空哨兵(详见 [[project-md5-null-sentinel]])
- **有效填充率因议题不同**:精准地域名义100%,但排除"其他"/"境外"后,城市养犬 76.5% 有效,婚俗改革 20.9% 有效
- **认证类型 33-72%** 填充(因议题而异),能识别大V/机构/普通/加V四档
- **话题字段 12-30%** 填充,不能作为主分类依据
- **用户画像字段严重稀疏**:出生月份 1-27%、感情状况 1%、学校 3.9%、公司 2.3%、兴趣标签 1-24%——**画像圈层不能直接切**

## 用户和传播的关键统计
### 用户重复度(大样本纠正了小样本)
- 单 csv 小样本:每用户 1.18-1.63 帖(错觉:用户级建模不可行)
- 3 csv 大样本(城市养犬):3.7 万帖 / 2.5 万独立用户 = 1.53 帖/用户,18.5% 用户≥2帖
- 3 csv 大样本(婚俗改革):7.4 万帖 / 2.4 万独立用户 = **3.05 帖/用户,31.6% 用户≥2帖**
- 结论:**大议题下有充足的用户级建模基础**,不是"1帖/用户"

### 传播图密度(大样本+POC 纠正)
- 单 csv 小样本以为"97.9% 帖子转发数=0,图极稀疏"
- 大样本+POC 实测:城市养犬 3 csv 里 32399 条有效转发边,79% 用户参与过转发交互;婚俗改革 84% 用户参与
- POC 单议题图规模:5-26 万节点,6-30 万边,最大连通分量 91-99.6%
- **图不稀疏,Leiden 完全可用**(模块度 0.77-0.89 极好)

### 转发数字段是废字段
- 转发数字段本身非0率仅 0.6-1.0%(采集快照问题,不是真实转发规模)
- 真实传播规模必须用 `groupby(md5_root_mid)` 后过滤 NULL 哨兵才准
- 类似:评论数、阅读数、点赞数字段非0率都 <5%,基本不可用

### 传播树规模(过滤NULL后)
- 每议题真实传播树数:城市养犬 3csv 有 768 棵、婚俗改革 3csv 有 660 棵、单热点事件 6287 棵
- 中位数树大小 = 1(独苗为主)
- 90 分位 = 8-9 帖
- **1-2 棵超大树承载 50-90% 帖子**(城市养犬 top2 = 23092+5363,婚俗改革 top1 = 65878)

### 时间粒度
- **秒级**(2025-02-28 16:46:44),Hawkes 完全适配
- 时间跨度:热点事件 ~10 天,传播案例 ~120 天,重大议题跨月甚至跨年

## 圈层信号可用性汇总(实测)
- **情绪**:100% 填充,6 类(中性/悲伤/惊奇/喜悦/愤怒/恐惧)+ 空。核心抓手
- **地域**:名义100%,有效20-80%(因议题而异),可切省级
- **涉及行业**:100% 填充,73-90% 有效,多标签(逗号分隔)。天然分类维度
- **认证类型**:33-72% 填充,分 bigv/org/verified/normal/unknown 五档
- **粉丝数**:100% 有值但 27-72% 为0(小微用户占多数)
- **用户画像**:全部 <25% 有效,基本放弃

## 因此推翻的算法方向(以及具体推翻原因)
- ~~**Louvain 单跑不适用**~~:已被 POC 推翻,图密度足够,Leiden 模块度 0.77-0.89
- ~~**node2vec/GNN 主线不可用**~~:数据清洗后完全可用,变成"论文对比方法"
- ~~**画像字段直接切圈层**~~:填充率不支持,仍然不可
- **SIR/SEIZ 主模型**:仍然不适合(S 未知),降级为热度曲线辅助
- **纯用户级 embedding 聚类**:用户已排除内容相似度评估维度,不做

## 因此保留/新提的算法方向(见 [[project-algorithm-decisions]] 详情)
- **主圈层**:Leiden 在转发图上——已 POC 验证
- **传播预测**:分层 Hawkes(5-8 维)+ XGBoost 学 α 调制——尚未 POC
- **情绪演化**:圈层-情绪马尔可夫链——尚未落地
- **反事实验证**:利用大V下场事件做 historical strategy validation

## 数据处理管线(实测)
- **索引层**:全字段+全文保留,Parquet + zstd 压缩
- **实测速度**:600 万行(6 个 zip)本地 CPU 单进程 8 分钟
- **实测输出大小**:单议题 3-4 GB Parquet(相当于原始 CSV 5-10x 压缩)
- **全量预估**:40-80 GB Parquet
- **索引产物结构**:每 zip 一个 Parquet,55 列(见 [[project-algorithm-decisions]] 中的字段清单)
