**规则**: `d41d8cd98f00b204e9800998ecf8427e` = MD5(空字符串),数据源用它表示"该字段值为空"。所有 MD5 字段的分析必须先过滤这个哨兵值。

**Why**: 用户 2026-07-25 指出"MD5 字段有大量空数据",经三个话题(城市养犬/婚俗改革/传播案例)3 csv 样本验证,发现完全一致的规律。数据采集时对空值填了 MD5("") 而不是 NULL,如果不识别这个哨兵,所有传播树统计会被夸大(把大量独立原创帖归为同一棵"空树")。

**How to apply**:
- 所有针对 MD5 字段的统计/聚合前,把 `d41d8cd98f00b204e9800998ecf8427e` 替换为 NULL
- 索引层的 md5_root_mid / md5_root_uid 字段必须做此规范化(已在 build_index.py 里实现)
- 传播树 = groupby(md5_root_mid) after filtering NULL sentinel

**观察到的哨兵分布规律**(基于 3 个议题各 3 csv 样本):
- MD5-作者ID / MD5-mid / MD5-id / MD5-父微博ID:0% 是哨兵(总是真实值)
- MD5-根微博mid:5-13% 是哨兵
- MD5-根微博用户UID:87-95% 是哨兵
- 两个"根字段"的哨兵状态**互斥**,即"归属传播链的帖子"两个根都填真实值,"独立原创帖"两个根都填哨兵

**推断的采集端逻辑**:
- 只有当帖子是"某条大传播链的一部分"时,根微博 ID 才会被写入真实值
- 独立的原创帖(没有引发转发的)—— 两个根字段都填空值哈希

**校正后的真实传播树规模**(基于 3 csv 样本,不是全 zip):
- 城市养犬:768 棵真实树,中位数=1帖,顶部2棵超大树(23092+5363 帖)占 77%
- 婚俗改革:660 棵真实树,顶部1棵超大树(65878 帖)占 90%
- 单 zip 全量(122 csv)估算:预计几千棵真实树,顶部十几棵大树承载主要传播

**对建模的直接影响**:
- 传播预测的"训练样本"应聚焦**顶部 5-20 棵大树/议题**,不是全体帖子
- 中位数=1 的独苗帖不参与传播模型训练
- Hawkes 事件序列丰度足够(单棵大树几千到几万条事件)
