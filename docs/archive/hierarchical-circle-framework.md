# 分层圈层框架:原子圈 → 元圈层

**创建**: 2026-07-26
**状态**: 方案文档,未实施。等 Leiden POC 扩到多话题后启动。
**位置**: 位于本竞赛的圈层识别层,是 [circle-identification-report.md](circle-identification-report.md) 的延伸。

---

## 1. 为什么需要分层?(核心动机)

### 1.1 单层 Leiden 的落地困境

我们在婚俗改革 3csv 数据上验证了 Leiden 圈层识别的**结构可靠性**:模块度 0.752、稳定性 100%、圈内互动占比 99%。但落地时面临三个问题:

**问题 1:圈数量爆炸**
- 单个话题得到 **517 个原子圈**
- 数据集有 8 个重大议题 + 263 个热点事件 + 114 个传播案例 = **~385 个话题**
- 如果每个话题几百个圈,全量数据会产生 **几万到十几万个原子圈**
- 策略层不可能针对这么多圈逐个设计引导策略

**问题 2:命名困难**
- 每个 Leiden 圈是一组具体用户 ID
- 圈内画像多样(省份熵 1.48,认证熵 0.6)——不像"福建媒体圈"这么简单
- **原子圈本身没有清晰的名字**,只有编号 CID=0/1/2...

**问题 3:跨话题不可比**
- 婚俗改革的 CID=1 和 AI 就业的 CID=1 是**完全不同的一批人**(用户跨话题 Jaccard 只有 0.01)
- 用户级的跨话题合并没有意义
- 策略层需要跨话题稳定的"圈层类型",不是话题特定的 ID

### 1.2 解决办法:两层框架

```
┌────────────────────────────────────────────────────────────┐
│  Layer 2: 元圈层原型(cross-topic,10-30 个)               │
│  例: "情绪扩散型"、"权威中心型"、"地域深耕型"...            │
│  用途: 策略层的作用对象,论文里的圈层分类                     │
├────────────────────────────────────────────────────────────┤
│  Layer 1: Leiden 原子圈(per-topic,每话题几百个)          │
│  例: 婚俗改革-CID=0, CID=1, ..., CID=516                   │
│  用途: 数据分析的基础单元,反事实验证的参考对象               │
└────────────────────────────────────────────────────────────┘
```

**核心思想**: 数据层保留 Leiden 的原子圈(不丢信息),策略层只面对元圈层(可解释、可命名、跨话题稳定)。每个原子圈都归属到一个元圈层类型。

## 2. 元圈层的物理意义

### 2.1 元圈层识别的到底是什么?

**不是识别成员**——跨话题的成员完全不同,识别成员没意义。
**是识别"类型"**——像识别"公司类型"一样(销售公司/科技公司/媒体公司),不看具体是哪家公司,看它有什么行为特征。

**类比**: 想象 100 家公司,每家都有销售部、研发部、财务部。销售部的具体员工每家不同,但"销售部"这个抽象类型跨公司稳定存在。

**元圈层就是圈层的抽象类型**。在婚俗改革里出现的"情绪扩散型圈"和 AI 就业里出现的"情绪扩散型圈",成员完全不同,但它们的**行为特征**相似——所以归为同一元圈层。

### 2.2 圈层与圈层的真正区别在哪三个层次

理解元圈层前,先搞清楚"圈层差异"有三个层次:

**层次 1:成员差异(表面)**
- 圈 A 和圈 B 由不同用户组成
- 这是废话,几乎所有论文停在这里

**层次 2:组成差异(中层)**
- 圈 A 里认证用户占 30%,圈 B 只占 5%
- 圈 A 主省份是浙江,圈 B 主省份是山东
- 已经有些描述价值,但静态

**层次 3:动力学差异(核心)**
- 圈 A 收到新信息后 1 小时内扩散完;圈 B 拖 12 小时
- 圈 A 情绪波动大;圈 B 一直中性
- 圈 A 是"信息起点"(信息从这里发出到其他圈);圈 B 是"信息终点"(只进不出)
- **这才是竞赛题目真正关心的**——因为策略引导的目标就是"改变传播动力学"

**元圈层用层次 3(动力学)+ 层次 2(组成)混合定义**。层次 1(成员)在跨话题时无意义,不使用。

### 2.3 为什么不显式做"用户角色"这一层?

一个自然的想法是引入第三层:"用户角色维度"(KOL / 桥接者 / 扩散者 / 围观群众)。但我们**不这样做**,原因:

- **用户角色决定圈的动力学**(自动因果):圈内 KOL 多 → 圈起始扩散快;圈内桥接者多 → 圈跨圈传播强
- **直接测圈的动力学**已经间接包含了角色信息
- 显式加一层角色维度是**冗余**,让方法复杂而无收益

**结论**: 只需要两层——原子圈(Leiden) → 元圈层(基于圈行为聚类)。不加用户角色层。

论文里可以说:"我们不显式建模用户角色,因为角色的作用已经通过圈层动力学特征间接反映。"

## 3. 元圈层的行为特征体系

每个原子圈被映射为一个**15-25 维的行为特征向量**,这个向量描述"圈是什么样的",而不是"圈里是谁"。

### 3.1 结构特征(圈本身的图性质,5-8 维)

| 特征名 | 定义 | 物理意义 |
|---|---|---|
| `size` | 圈内用户数 | 圈的规模 |
| `edge_count` | 圈内边数 | 圈的互动量 |
| `density` | 边数 / (size × (size-1) / 2) | 圈内连接紧密度,越高越像"团" |
| `external_edge_ratio` | 圈外边数 / (圈外边+圈内边) | **桥接性**:值高表示圈对外交流多 |
| `avg_degree` | 圈内平均度数 | 平均活跃度 |
| `degree_variance` | 圈内度数方差 | **层级性**:高方差 → 有中心节点(KOL);低方差 → 扁平 |
| `top_node_dominance` | 最高度数用户的度数 / 平均度数 | KOL 中心化程度 |
| `clustering_coeff` | 平均聚类系数 | 邻居互相连接程度 |

### 3.2 动力学特征(圈的传播行为,6-10 维)

| 特征名 | 定义 | 物理意义 |
|---|---|---|
| `avg_propagation_depth` | 圈内所有传播链的平均深度 | 传播是浅扩散还是深链条 |
| `max_propagation_depth` | 圈内最深传播链 | 传播的极限深度 |
| `time_span` | 圈内最后一帖 - 第一帖 | 圈的活跃时长 |
| `burst_intensity` | 最高峰小时帖数 / 平均小时帖数 | 是"爆发式"还是"平稳型" |
| `time_to_peak` | 圈第一帖到峰值时刻的时长 | 反应速度 |
| `sentiment_variance` | 圈内情绪分布的熵 | 情绪是否剧烈波动 |
| `dominant_sentiment` | 主情绪(One-Hot) | 该圈整体情绪基调 |
| `outflow_ratio` | 圈作为父节点被外部转发的比例 | **信息源程度**:值高 → 圈是起点 |
| `inflow_ratio` | 圈作为子节点转发外部的比例 | **信息汇程度**:值高 → 圈是终点 |
| `topic_drift` | 圈内前后期话题词的差异 | 议题内容是否漂移 |

### 3.3 组成特征(圈内用户的统计,4-7 维)

| 特征名 | 定义 | 物理意义 |
|---|---|---|
| `province_purity` | 主省份的用户占比 | 地域集中度 |
| `province_top1` | 主省份类别(One-Hot 或 label) | 主要来自哪里 |
| `industry_purity` | 主行业的用户占比 | 领域集中度 |
| `industry_top1` | 主行业类别 | 圈的领域标签 |
| `auth_bigv_ratio` | 大V 用户占比 | KOL 密度 |
| `auth_org_ratio` | 机构用户占比 | 官方组织密度 |
| `auth_normal_ratio` | 普通用户占比 | 大众用户密度 |
| `avg_log_followers` | 平均 log(粉丝+1) | 平均影响力量级 |
| `median_log_followers` | 中位数 log(粉丝+1) | 影响力中枢(避开长尾干扰) |

### 3.4 特征总数

- 结构特征:约 8 维
- 动力学特征:约 10 维
- 组成特征:约 8 维
- **合计 ≈ 26 维圈层行为向量**

**说明**: 部分类别型特征(如 `province_top1`)会 One-Hot 展开,实际维度会更高。但主省份 top1 只取几个大类(如"华东"、"华北"、"华南"),避免过高维度。

## 4. 元圈层识别算法流程

### 4.1 总体流程

```
输入: 多个话题的 Leiden 原子圈结果(每话题几百个圈)
  ↓
Step 1: 对每个原子圈计算 26 维行为特征向量
  ↓
Step 2: 跨话题合并所有圈的特征向量
  → 婚俗改革 517 个 + AI就业 X 个 + ... = 总共 Y 个圈的特征向量
  ↓
Step 3: 对 Y 个"圈特征向量"做二次聚类(KMeans 或 HDBSCAN)
  → 得到 10-30 个元圈层
  ↓
Step 4: 为每个元圈层自动生成标签
  → "情绪扩散型"、"权威中心型"、"地域深耕型"...
  ↓
Step 5: 每个原子圈被打上元圈层标签
  → 婚俗改革-CID=173 属于"情绪扩散型"
  → AI就业-CID=45 也属于"情绪扩散型"
  → 跨话题稳定性验证
```

### 4.2 Step 1 详解:圈特征向量构造

对每个 Leiden 原子圈 C:

```python
def compute_circle_features(circle_users, edges, posts):
    """
    circle_users: 该圈的用户 ID 列表
    edges: 圈涉及的所有边(圈内+圈外)
    posts: 圈内用户发的所有帖子(带时间戳、情绪、行业等)
    """
    # 结构特征
    internal_edges = edges[edges 双端都在 circle_users]
    external_edges = edges[edges 一端在圈内一端在圈外]

    size = len(circle_users)
    density = 2 * len(internal_edges) / (size * (size - 1))
    external_edge_ratio = len(external_edges) / (len(external_edges) + len(internal_edges))
    degrees = compute_degrees(circle_users, internal_edges)
    degree_variance = np.var(degrees)
    top_node_dominance = max(degrees) / mean(degrees)

    # 动力学特征
    ts = posts['ts']
    time_span = ts.max() - ts.min()
    hourly_counts = posts.groupby(hour(ts)).size()
    burst_intensity = hourly_counts.max() / hourly_counts.mean()

    child_posts = posts[posts.is_original == False]
    outflow = edges[edges.parent_user_in_circle & edges.child_user_out_circle].count()
    inflow  = edges[edges.parent_user_out_circle & edges.child_user_in_circle].count()

    sentiment_dist = posts['sentiment'].value_counts(normalize=True)
    sentiment_variance = entropy(sentiment_dist)

    # 组成特征
    province_dist = posts['province'].value_counts(normalize=True)
    province_purity = province_dist.iloc[0]

    auth_bigv_ratio = (posts['auth_tier'] == 'bigv').mean()

    ... # 略

    return feature_vector  # 26 维
```

### 4.3 Step 3 详解:元圈层聚类

**首选 KMeans**:
- k = 10-30(通过肘部法则或轮廓系数确定)
- 特征提前标准化(StandardScaler)
- 类别型特征已 One-Hot,直接可用

**次选 HDBSCAN**:
- 自动定簇数
- 但会产生噪声圈(标为 -1),需要额外处理

**为什么这次不用 Leiden 二次聚类**:
- Leiden 需要图,但"圈的特征向量"是欧氏空间,不是图
- 除非把圈两两算相似度构造相似度图 → 复杂化,不必要

### 4.4 Step 4 详解:元圈层自动命名

每个元圈层生成两级命名:

**级别 1:数值特征描述**
根据元圈层里所有圈的**均值/中位数**特征给出:
- `structure_signature`: 高密度 / 低密度 / 中密度
- `dynamics_signature`: 快扩散 / 慢扩散 / 爆发型
- `role_signature`: 信息源 / 信息汇 / 桥接型
- `composition_signature`: KOL 主导 / 大众主导 / 机构主导

**级别 2:人类可读标签**
根据数值特征组合映射到 6-10 个预定义标签:
- **"情绪扩散型"** = 密度高 + 爆发型 + 情绪熵高 + 大众主导
- **"权威中心型"** = 度数方差高 + KOL 主导 + 信息源
- **"地域深耕型"** = 省份纯度高 + 慢扩散 + 大众主导
- **"跨圈桥梁型"** = 外边比高 + 桥接系数高
- **"专业阵地型"** = 行业纯度高 + 机构占比高 + 信息源
- **"围观终点型"** = 信息汇比高 + 大众主导 + 情绪中性
- **"话题深耕型"** = 时间跨度长 + 话题漂移小
- **"爆发短暂型"** = 峰值高 + 时长短

**命名规则可以固化为一个决策树**,论文里可以清楚描述。

## 5. 预期结果与论文加分点

### 5.1 预期得到的元圈层类型

基于对婚俗改革 POC 的观察,我们**预期**跨话题会稳定出现 8-15 种元圈层。列几个典型:

**典型 1:大众围观圈**
- 特征:密度中等、大众用户主导、情绪中性、多为终点
- 例子:婚俗改革的浙江/福建普通用户互转圈
- 策略含义:引导它们需要**通过邻近的信息源**,直接影响成本高

**典型 2:权威 KOL 圈**
- 特征:小规模、KOL 主导、信息源、影响力集中
- 例子:婚俗改革的媒体机构互动圈
- 策略含义:策略的**主要作用点**——影响 KOL 就能带动整个话题

**典型 3:情绪爆发圈**
- 特征:密度极高、爆发型、情绪熵极高(负面情绪突出)
- 例子:婚俗改革中的愤怒散户圈
- 策略含义:**风险监测重点**,可能是策略失控的信号

**典型 4:地域深耕圈**
- 特征:省份纯度极高、慢扩散、话题稳定
- 例子:某省本地媒体的话题深耕圈
- 策略含义:适合做**地域性引导实验**

**典型 5:跨圈桥梁圈**
- 特征:外边比高、桥接性强
- 例子:连接大 V 圈和大众圈的中层用户
- 策略含义:**信息渗透的关键节点**,策略层重点关注

### 5.2 论文写作提示

**"网络关系提取"部分**(接续 [circle-identification-report.md](circle-identification-report.md)):

> 在完成基于关系网络的 Leiden 原子圈识别后,我们发现单话题下产生的圈层数量(517 个)难以直接应用于策略层。为解决此问题,我们提出**分层圈层框架**:在原子圈之上引入元圈层(meta-community)概念。元圈层通过对原子圈的行为特征进行二次聚类得到,每个原子圈被归属到一个元圈层类型。
>
> 元圈层的定义**不依赖具体成员**,而依赖圈本身的三类行为特征:结构特征(密度、桥接性、层级性)、动力学特征(扩散速度、情绪波动、信息流向)、组成特征(用户身份分布、地域分布)。共计 26 维特征向量。这样的定义允许元圈层**跨话题稳定存在**——不同议题下的原子圈成员完全不同,但可能属于同一元圈层类型。
>
> 实验发现,X 个议题共产生 Y 个原子圈,通过二次聚类得到 Z 个元圈层,其中 W 个元圈层在多个议题中反复出现,证明社交媒体的圈层类型有跨话题稳定性。

**"跨话题稳定性验证"**:

> 我们通过两项指标验证元圈层的跨话题稳定性:
> 1. **元圈层出现频率**:某元圈层在多少个议题中出现。稳定的元圈层应在 >50% 议题中出现。
> 2. **元圈层内部一致性**:同一元圈层下的不同话题原子圈,其行为特征的方差应显著低于跨元圈层。
>
> 实验结果显示 W 个元圈层跨话题稳定出现,证明这些类型是社交媒体传播的通用规律,而非特定话题的偶然产物。

### 5.3 对下游模型的价值

**传播预测层**:
- Hawkes 过程按元圈层建维度(10-30 维),而非按原子圈(几万维)——参数可估计
- 元圈层的动力学特征本身就是 Hawkes 参数的先验(比如"爆发型"元圈层的 α 参数应该更大)

**策略优化层**:
- 策略作用对象是元圈层类型,不是具体圈 ID
- 举例:"针对情绪爆发圈的降温策略",可以在多个话题里复用
- 反事实验证:同类元圈层在不同话题里的历史行为可作为对比

## 7. 已知局限

### 7.1 元圈层数量的不确定性

- 事先不知道会得到多少个元圈层
- 需要通过肘部法则或轮廓系数试出来
- 可能得到 5 个太粗,可能得到 40 个太细

### 7.2 命名规则的主观性

- "情绪扩散型" / "权威中心型" 这些名字是我们**预设**的
- 实际聚类结果可能不完全对应这些预设名
- 需要在实验后**根据实际簇特征调整命名规则**

### 7.3 未处理水军问题

- 元圈层的"密度高 + 内部互转多"特征可能被水军军团模拟
- 我们暂不做水军过滤,但论文里需说明这一限制
- 参考建议:直接在"结果讨论"部分声明:"本研究不做水军检测,可疑规律可能受此影响。"

### 7.4 内容维度未加

- 元圈层现在只用结构+动力学+组成,不用文本内容
- 如需加内容维度,参考 [content-dimension-plan.md](content-dimension-plan.md)
- 补充方式:在 26 维行为特征后拼接"圈内文本 embedding 均值"(如 BGE 512 维)

## 附录 A:与用户初始设计的九圈层对照

用户在讨论初期曾根据业务直觉设计九个圈层(双向传播枢纽、稳定跨群桥接者、稳定源发触达者、稳定扩散放大者、机构高势能传播者、议题高势能者、专业高势能者、稳定议题深耕者、大众触达者)。

经过讨论,这些**大部分是"角色描述"而非"社群描述"**——两个"跨群桥接者"未必在同一个圈里,他们扮演同样角色但不是社群意义上的一伙人。

**在本框架里的对应关系**:
- 用户的九个圈层**大致对应角色维度**,而非社群维度
- 本框架不显式做角色维度层,因为角色的作用已通过圈的动力学特征间接反映
- 但用户的九类可以作为**元圈层自动命名规则的参考词表**——如果算法得出的元圈层特征与"跨群桥接者"匹配,可以直接借用这个名字

**给论文的启示**:
若元圈层聚类得到的类别与用户预设九类高度对应,可写:"实验结果与业务直觉设定的用户角色分类高度一致,验证了从数据驱动路径识别圈层类型的客观性"——**既承认用户直觉的合理性,又用数据佐证**。

## 附录 B:决策清单

写文档时的关键选择,便于后续复盘:

| 决策点 | 选择 | 理由 |
|---|---|---|
| 用户角色维度是否独立 | 不独立,合并到动力学 | 用户角色 → 圈动力学,是自动因果,冗余 |
| 水军可疑度维度 | 不做 | 启发式规则不可靠,启发式判据几乎没意义(用户明确表态) |
| 内容维度是否强制 | 不强制,作为可选 | 现阶段结构+动力学已够,内容在需要时补 |
| 元圈层数量 | 10-30(试出来) | 太少太粗,太多失去简化价值 |
| 聚类方法 | KMeans 优先,HDBSCAN 备选 | 特征是欧氏空间,KMeans 直接 |
| 命名方式 | 决策树自动 + 6-10 个预定义标签 | 自动可复现,标签保证可读 |
