# 圈层识别算法对比实验报告

**任务**: 从社交媒体传播数据中识别用户圈层
**数据集**: 婚俗改革议题(3 csv 样本,358212 帖,37022 有互动用户,49778 边)
**实验时间**: 2026-07-26
**执行环境**: RTX 4090 24GB / 24 vCPU / 62GB RAM / Python 3.10

---

## 1. 研究背景

### 1.1 圈层识别在整体建模中的位置

课题"社交媒体圈层用户引导策略与效果预测"按三层建模:

1. **圈层识别层** — 把千万级用户映射到有限个"决策群体"
2. **传播预测层** — 给定圈层结构和策略,预测传播效果
3. **策略优化层** — 通过遍历策略搜索,评估 ROI

本文档聚焦第一层。**只有先识别出稳定、有含义的圈层,后续的传播建模和策略推演才有落地对象**。

### 1.2 什么是"圈层"?

在这类研究里,"圈层"有三种可能含义:

- **兴趣圈层**(内容驱动):讨论宠物、讨论房价、讨论娱乐,可能互相不认识
- **社交圈层**(关系驱动):互相关注、转发、评论构成的连接群体
- **画像圈层**(属性驱动):学生 / 打工人 / 宝妈 / 退休群体

**我们讨论后选择了社交圈层作为主定义**,原因见下节。

### 1.3 评估标准的设定与哲学

我们(用户)明确了三条评估标准:

1. **圈层内传播一致性** — 圈内互动 > 圈间互动
2. **圈层稳定性** — 不同随机种子下结果一致
3. **圈层可解释性** — 能起清晰名字

**明确排除了"内容相似度"这一维度**。理由:一个真实用户不会永远只讨论一个话题,兴趣多元化;但如果两个用户之间**有转发/评论互动**,他们本质上可以看作在同一个圈层里(共享同一信息流)。因此"关系"比"内容"更适合作为圈层定义。

这个选择直接决定了后续算法选型的方向:**基于图结构的算法优先于基于内容的算法**。

## 2. 实验设计

### 2.1 需要回答的三个核心问题

Q1. Leiden 只用图结构,忽略了用户画像(地域、行业、认证)和内容,这是不是缺陷?

Q2. 话题内建圈是不是"伪问题"? — 讨论同一话题的用户,是不是天然就是一个大圈,再划分毫无意义?

Q3. Leiden 之外的算法(node2vec、LINE、纯画像切分、结构+画像融合)在同一数据集上效果如何?

### 2.2 实验组:5 种算法

| 编号 | 算法 | 信号来源 | 类型 |
|---|---|---|---|
| 1 | **Leiden** | 图结构 | 直接输出社区(模块度优化) |
| 2 | **node2vec + HDBSCAN** | 图结构 | 图嵌入 → 密度聚类 |
| 3 | **LINE + HDBSCAN** | 图结构 | 图嵌入 → 密度聚类 |
| 4 | **profile_kmeans** | 用户画像(不看图) | 属性向量 → K-means |
| 5 | **fused** (node2vec ‖ 画像) | 图结构+画像拼接 | 拼接向量 → HDBSCAN |

**为什么这样组合**:
- 1/2/3 都是"纯图结构算法",互相对照可判断 Leiden 是否真的更好
- 4 是"纯画像算法",对照 1 可以判断"图算法是否比简单画像切分多加信息"
- 5 是"融合方案",探索"结构 + 画像"是否更好

### 2.3 数据准备流程

```
原始 CSV (GB18030 编码)
    ↓ build_index.py
索引 Parquet (55 列/每帖一行)
    ↓ prepare_data.py
    ├─→ edges.parquet     (src_author, dst_author, weight)
    └─→ user_features.parquet (province, auth_tier, industry, sentiment, log_followers, n_posts)
    ↓
5 种圈层算法
    ↓
partition_<method>.parquet (md5_author, community_id)
    ↓ evaluate.py
results.csv + consensus_matrix.csv + human_check_top10.md
```

**图构造**:
- 节点 = 用户(MD5-作者ID)
- 边 = 转发关系:子帖作者 → 父帖作者(通过 MD5-父微博ID 查作者)
- 权重 = 两用户之间的互动次数
- 过滤 = 去自转发、去 NULL 哨兵(`d41d8cd98f00b204e9800998ecf8427e = MD5("")`)、无向图

**数据实况**:
- 帖数: 358,212
- 独立用户: 94,122
- 参与互动的用户(在图里): **37,022**
- 独特边: 49,778

## 3. 五种算法详解

### 3.1 Leiden(主线)

**类型**: 直接社区发现算法(不需要下游聚类)

**原理**:
- 优化目标 = **模块度 Q**(见下节详解)
- 迭代过程:
  1. 每个节点初始化为独立社区
  2. 尝试把节点移入邻居社区,如果模块度增加就接受
  3. 收敛后进行 **refinement**(Leiden 相比 Louvain 的关键改进):在每个社区内部重新做一次精细划分,保证**社区内部连通**(Louvain 不保证)
  4. 把每个社区聚合成一个"超级节点",重复步骤 1-3,直到不能再优化

**优点**:
- 只需要图结构,无需节点特征
- 无需预设社区数
- 稳定性好(refinement 阶段消除了 Louvain 的随机性问题)
- C++ 底层(igraph),多核加速

**输出**: 每个用户直接得到一个 community_id。

**实现**: `leidenalg.find_partition(G, la.ModularityVertexPartition, weights='weight')`

### 3.2 node2vec + HDBSCAN

**类型**: 图嵌入 + 下游聚类(两阶段)

**原理**:
- **node2vec**:从每个节点出发做随机游走(BFS/DFS 偏向由参数 p、q 控制),把序列当"句子"喂给 word2vec 得到节点向量
- **HDBSCAN**:对向量做密度聚类,自动识别簇数和噪声点

**特点**:
- 向量包含"节点在网络中的位置"信息
- 结构相似的节点(邻居相似)向量也相近
- HDBSCAN 会把稀疏区域的点标记为噪声(-1),因此**有效节点少于总节点**

**实现**:
- pecanpy(numba/多核 CPU 加速,比 karateclub 快 100 倍以上)做 node2vec
- sklearn HDBSCAN 做聚类

### 3.3 LINE + HDBSCAN

**类型**: 图嵌入 + 下游聚类(两阶段)

**原理**:
- **LINE**:直接优化两种邻近度
  - **一阶邻近**:直连的节点向量应该相近
  - **二阶邻近**:有共同邻居的节点向量应该相近
- 用 skip-gram 式的负采样目标函数训练
- 相比 node2vec,LINE 不需要显式做随机游走

**特点**:
- 训练极快(PyTorch GPU 版实测 0.2 秒完成)
- 对稀疏图友好
- 需要下游 HDBSCAN 得社区

**实现**: 手写 PyTorch GPU 版(4090)+ sklearn HDBSCAN。

### 3.4 profile_kmeans(纯画像切分,基线)

**类型**: 属性聚类,**不看图结构**

**用到的特征**(每个用户变成 70 维向量):
- 主省份(One-Hot,34 维)
- 认证等级(One-Hot,5 维:bigv/org/verified/normal/unknown)
- 主导情绪(One-Hot,~7 维)
- 主行业(One-Hot,~20 维)
- log(粉丝数+1)
- 帖子数

**做法**: 上面 70 维向量 → K-means (K = Leiden 的社区数 517,保证可比)

**目的**: 作为"最简单基线",诊断 Leiden 是否比简单画像切分多提供信息。

### 3.5 fused(结构 ‖ 画像 融合)

**类型**: 简单拼接融合

**做法**:
- 拿 node2vec 的 64 维向量
- 拿 profile 的 70 维向量
- **直接拼接**为 134 维向量
- 跑 HDBSCAN

**目的**: 探索"结构+画像"是否比单独使用更好。

## 4. 评估指标详解

### 4.1 Modularity(模块度)—— 衡量圈层的结构强度

**含义**:
一个社区划分的模块度衡量的是:**圈内的边**比"如果边随机分布"预期的圈内边**多了多少**。

**数学定义**:
```
Q = Σ_i [ e_ii - (a_i)^2 ]
```
其中:
- `e_ii` = 圈 i 内部边数 / 总边数
- `a_i` = 圈 i 中所有节点的度数之和 / (2 * 总边数)
- `(a_i)^2` = 如果边完全随机分布,圈 i 内应有多少边(期望值)

**解读标尺**:
| Q 范围 | 含义 |
|---|---|
| < 0.3 | 结构弱,和随机图差不多 |
| 0.3 - 0.5 | 有一定结构 |
| 0.5 - 0.7 | 结构较强 |
| > 0.7 | 结构极强 |

**为什么这个指标重要**:模块度是社区发现的"金标准",一个划分不管你怎么起名、怎么解释,只要圈内互动明显多于随机情况,它就是有信息量的。

### 4.2 稳定性 ARI(Adjusted Rand Index)

**含义**: 两个划分有多"像"。

**计算**: 数据集中的所有用户对,统计两个划分把这对用户分到同一圈或不同圈的一致性,并针对"随机情况下的一致性"做修正。

**取值范围**:
- ARI = 1:两个划分完全相同
- ARI = 0:两个划分和随机划分一样一致(=没有关系)
- ARI < 0:比随机还差(几乎不会出现在合理算法上)

**用途**:
- **同算法多种子 ARI**:衡量算法稳定性
- **不同算法两两 ARI**:衡量共识度

### 4.3 画像一致性(圈内熵)

**含义**: 对每个圈,统计圈内所有用户的省份分布,计算香农熵。熵越低,圈内省份越集中。

**用到的四个字段**: 省份 / 认证等级 / 主行业 / 主导情绪。

**注意**: 这个指标**不是越低越好**。profile_kmeans 圈内画像熵极低(0.17)——但那是因为它本身就是按画像切的,是**同义反复**。这个指标只是让我们看到"圈层是否和画像重合"。

### 4.4 有效节点数

**含义**: 一个算法产出的划分覆盖了多少节点。

**背景**: HDBSCAN 会把稀疏区域的点标记为"噪声"(community_id = -1),这些点没有归属圈层。Leiden 不产生噪声,所有节点都有归属。

## 5. 实验结果

### 5.1 Modularity 对比

| 算法 | Modularity | 有效节点 |
|---|---|---|
| **Leiden** | **0.752** | 37022 (100%) |
| node2vec + HDBSCAN | 0.441 | 24440 (66%) |
| LINE + HDBSCAN | -0.013 | 20321 (55%) |
| profile_kmeans | -0.011 | 37022 (100%) |
| fused | -0.035 | 18891 (51%) |

**解读**:
- Leiden 模块度 **0.752**,达到"结构极强"标准
- node2vec 也不错(0.441,"有一定结构")
- LINE、profile_kmeans、fused 的模块度都接近 0 或为负,说明这些划分**在图结构维度上没有意义**

### 5.2 稳定性

- **Leiden** 三种子稳定性 ARI = **0.955**(极稳定,几乎不受随机种子影响)

### 5.3 共识度矩阵(核心)

|  | leiden | node2vec | line | profile_km | fused |
|---|---|---|---|---|---|
| **leiden** | 1.00 | **0.88** | **0.75** | **0.04** | 0.25 |
| node2vec | 0.88 | 1.00 | **0.91** | 0.04 | 0.31 |
| line | 0.75 | 0.91 | 1.00 | 0.02 | 0.23 |
| profile_km | 0.04 | 0.04 | 0.02 | 1.00 | 0.28 |
| fused | 0.25 | 0.31 | 0.23 | 0.28 | 1.00 |

**关键观察**:

**(A) 三种图算法两两 ARI 0.75-0.91** — 高度一致
→ 说明它们看到的是**同一个客观存在的东西**(图结构)
→ 反驳了"话题内建圈是伪问题"的担心,如果是随机划分,ARI 应该接近 0

**(B) 图算法 vs profile_kmeans ARI 0.02-0.04** — 几乎正交
→ "**图上的圈层结构**"和"**画像切分**"是**两码完全不同的东西**
→ 如果 Leiden 只是"变相在按地域切",这个 ARI 应该 > 0.5
→ 因此 Leiden 抓到了画像之外的信号——即"因互动关系形成的社群"

**(C) fused 和所有算法 ARI 都 <0.32**
→ 简单拼接融合的效果最差
→ 结构信号被画像信号"稀释",两边都不像

| 3 | 1,976 | 江苏省 | normal | 娱乐 | 中性 | 3.17 |
| 4 | 1,868 | 浙江省 | normal | 娱乐 | 中性 | 3.11 |
| 5 | 1,686 | 浙江省 | normal | 娱乐 | 中性 | 4.32 |
| 6 | 1,572 | UNKNOWN | normal | 公安 | 中性 | 3.61 |

**观察**:
- 圈内**跨地域**:top 10 里有福建、浙江、江苏、山东、UNKNOWN 等多个省份的圈

**Leiden vs profile_kmeans 的 ARI = 0.04**
→ 按我们事先定的判据(< 0.3 为"图结构信号显著独立于画像"):
→ **Leiden 抓到了画像之外的信号,值得作为主线**

## 6. 对研究问题的回答

**Q1. Leiden 忽略画像/内容是不是缺陷?**

不是缺陷,是特性。数据说明:
- 图结构圈层 vs 画像切分 ARI 只有 0.04(几乎正交)
- 意味着**"因互动关系形成的社群"和"同省同行业的集合"是两码不同的东西**
- 策略引导应该针对"有实际互动关系的用户群",不是"陌生的同省人"

如果加内容维度,得到的会是"讨论内容相近的一批用户"——但这些用户可能没有转发/评论互动,信息传播不通畅。**从策略引导的实操角度,基于互动关系的圈层更有价值**。

**Q2. 话题内建圈是不是伪问题?**

不是伪问题。反驳依据:
- Leiden 模块度 0.752,远高于随机图期望值(接近 0)
- 三种独立的图算法(Leiden、node2vec、LINE)之间 ARI 高达 0.75-0.91,说明它们看到了同一个客观结构
- 如果话题内是均匀大圈,任何算法切都会得到低模块度、低共识度

**但需要精确表述**: 圈层含义是"**该话题下由某某类用户组成的互动子群**",不是"**泛社交网络的圈层**"。跨话题不合并——用户 Jaccard(城市养犬 ∩ 婚俗改革)仅 0.01。

**Q3. 应该选哪个算法?**

**Leiden**,理由:
1. Modularity 最高(0.75 vs node2vec 0.44)
2. 有效节点 100%(node2vec/LINE 只覆盖 55-66%)
3. 稳定性极好(3 种子 ARI = 0.955)
4. 输出社区直接可用,不需要下游聚类
5. 与画像切分正交(ARI = 0.04),证明多加了信息
6. C++ 底层多核,单议题 26 万节点 27 秒完成

保留 node2vec / LINE 作为**论文对比方法**——它们的存在(与 Leiden 高共识度)反证了 Leiden 圈层的客观性。

## 8. 已知局限与后续工作

### 8.1 本 POC 的局限

1. **只在婚俗改革一个议题上验证**——需要在城市养犬、生育话题等更多议题上重跑,看结论是否稳健
2. **HDBSCAN 单核瓶颈**——3 次 HDBSCAN 占了 POC 总时间 82%,大规模跑时需换 cuml.HDBSCAN 或 KMeans
3. **未评估内容维度**——虽然评估标准里明确不加内容相似度,但作为对比可以补一个"内容 embedding + HDBSCAN"看看
4. **头部社区过大**——Leiden 的 CID=0 有 7281 用户(占 20%),可能需要 resolution > 1 或递归 Leiden 细分

### 8.2 论文写作用的重点

如果你要写"网络关系提取"部分,重点强调:

1. **选择 Leiden 而非 Louvain 的理由**: refinement 保证社区内连通、随机稳定性、比 Louvain 快 20-50%
2. **选择 Leiden 而非 node2vec/LINE**: 直接优化模块度、100% 有效覆盖、无需下游聚类
3. **对比实验的必要性**: 用 5 种算法的共识度矩阵证明"话题内圈层客观存在,不是算法伪影"
4. **与画像切分正交(ARI=0.04)**: 证明图结构信号独立于用户属性,是新增信息

### 8.3 下一步

## 附录 A: 关键概念速查

- **模块度(Modularity)**: 一个社区划分的"圈内边比随机情况多多少"
- **ARI(Adjusted Rand Index)**: 两个划分的相似度,范围 [-1, 1],1=完全相同,0=随机
- **HDBSCAN**: 层次密度聚类,自动定簇数并识别噪声,是图嵌入方法的下游步骤
- **Leiden refinement**: 每次迭代后在社区内部再做一次精细划分,保证连通性(Louvain 缺失)
- **NULL 哨兵**: `d41d8cd98f00b204e9800998ecf8427e` = MD5(""),数据集用它表示空值
- **有效节点**: 有归属圈层的节点数,HDBSCAN 会把稀疏区域标为噪声(-1)不计入
